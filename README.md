## Завдання 2. Проходження ієрархії вручну

```Команда 1:
dig @10.53.0.2 ns.s06.lab A +norec

;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 50607
;; flags: qr; QUERY: 1, ANSWER: 0, AUTHORITY: 1, ADDITIONAL: 2

;; AUTHORITY SECTION:
lab.                    172800  IN      NS      ns1.nic.lab.

;; ADDITIONAL SECTION:
ns1.nic.lab.            172800  IN      A       10.53.0.3

;; Query time: 81 msec
;; SERVER: 10.53.0.2#53(10.53.0.2) (UDP)


Команда 2:
dig @10.53.0.3 ns.s06.lab A +norec

;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 55986
;; flags: qr; QUERY: 1, ANSWER: 0, AUTHORITY: 1, ADDITIONAL: 2

;; AUTHORITY SECTION:
s06.lab.                3600    IN      NS      ns.s06.lab.

;; ADDITIONAL SECTION:
ns.s06.lab.             3600    IN      A       10.53.1.1

;; Query time: 80 msec
;; SERVER: 10.53.0.3#53(10.53.0.3) (UDP)


Команда 3:
dig @10.53.1.1 ns.s06.lab A +norec

;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 51796
;; flags: qr aa; QUERY: 1, ANSWER: 1, AUTHORITY: 1, ADDITIONAL: 1

;; ANSWER SECTION:
ns.s06.lab.             90      IN      A       10.53.1.1

;; AUTHORITY SECTION:
s06.lab.                90      IN      NS      ns.s06.lab.

;; Query time: 0 msec
;; SERVER: 10.53.1.1#53(10.53.1.1) (UDP)

```

| Сервер | status | flags | ANSWER | AUTHORITY | ADDITIONAL |
|---|---|---|---|---|---|
| 10.53.0.2 |NOERROR |qr |0 |1 |2 |
| 10.53.0.3 |NOERROR |qr |0 |1 |2 |
| 10.53.1.1 |NOERROR |qr aa |1 |1 |1 |

Вивід `dig ns.sNN.lab A +trace`:

```; <<>> DiG 9.18.39-0ubuntu0.24.04.8-Ubuntu <<>> ns.s06.lab A +trace
;; global options: +cmd
.                      84238   IN      NS      a.root-servers.net.
;; Received 59 bytes from 10.53.0.53#53(0.0.0.0) in 0 ms

lab.                   172800  IN      NS      ns1.nic.lab.
;; Received 111 bytes from 10.53.0.2#53(10.53.0.2) in 80 ms

s06.lab.               3600    IN      NS      ns.s06.lab.
;; Received 97 bytes from 10.53.0.3#53(10.53.0.3) in 41 ms

ns.s06.lab.            90      IN      A       10.53.1.1
s06.lab.               3600    IN      NS      ns.s06.lab.
;; Received 97 bytes from 10.53.1.1#53(10.53.1.1) in 0 ms

```

| Запит | TTL запису NS | Прапорець `aa` | Секція, у якій міститься NS |
|---|---|---|---|
| `dig @10.53.0.3 sNN.lab NS +norec` |3600 |Відсутній (лише qr) |AUTHORITY  |
| `dig @10.53.1.1 sNN.lab NS +norec` |90 |Присутній (qr aa) |ANSWER |

1. Які відповіді є відсиланнями і за якими ознаками це визначено?
Відсиланнями є відповіді від серверів 10.53.0.2 та 10.53.0.3, оскільки секція ANSWER у них порожня, а в секції AUTHORITY міститься посилання на DNS-сервер наступного рівня.
2. Для чого у відповіді TLD присутній запис у секції ADDITIONAL і що сталося б, якби його не було?
Він містить IP-адресу авторитативного сервера (glue record). Якби цього запису не було, резолвер не зміг би напряму дізнатися адресу наступного сервера для продовження пошуку.
3. Яка з двох копій запису NS є авторитативною і чому?
Авторитативною є копія на моєму сервері 10.53.1.1, оскільки він безпосередньо відповідає за мою зону і видає відповідь із прапорцем aa.
